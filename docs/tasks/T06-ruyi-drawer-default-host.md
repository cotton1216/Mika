# T06 · 如意抽屉默认展开电脑列表 + 唯一在线机自动连接

- **任务ID**：T06

## 一、目标

1. 如意会话抽屉顶部的「我的电脑」列表，**每次打开抽屉即处于展开态**，用户无需再点一次才能看到全部电脑。
2. 已登录、当前无连接、且**恰好一台**电脑在线时，**进入如意即自动连上该机**；抽屉首行直接显示该机名与「当前连接 · 在线」，会话列表随即自动拉取。

## 二、范围

### 本期做

- `SessionDrawer.kt`：`hostsExpanded` 初值由 `false` 改为 `true`，并更新相邻的设计注释。
- `RemoteSession.kt`：新增「唯一在线机自动连接」判定 + 一次性/抑制标记；`refreshHosts()` 成功后调用。

### 本期不做

- 两台及以上在线时的默认选择（维持人工点选）。
- 记住上次连接的主机（需持久化，另立任务）。
- 桌面端、中继侧改动。
- 自动连接后的失败自动重试。

## 三、方案要点

| 决策点 | 结论 | 理由 |
| --- | --- | --- |
| 触发点 | `refreshHosts()` 成功后判定 | 同时覆盖冷启动 `restore()`、抽屉 20s 轮询、手动刷新，无需新增生命周期钩子 |
| 判定条件 | 已登录 + 无连接 + 无连接中 + 在线机恰好 1 台 | 收窄条件，避免在多机场景「猜」一台 |
| 重复触发防护 | `autoConnectTried` 记录已尝试 hostId | 轮询每 20s 一次，无标记会反复 `connect`，中继同一 client 只保留一条链路，导致刚建好的链路被替换 |
| 手动断开 | `autoConnectSuppressed = true`，本次登录内不再自动连 | 否则下一轮轮询会把用户刚断开的机器连回去 |
| 解除抑制 | 用户手动连接任意主机时清空 | 此时用户意图明确 |
| 失败处理 | 不自动重试 | `ConnectionEpoch` 语义下与轮询叠加会造成链路反复替换；失败态由抽屉的展开列表 + 重试入口兜底 |
| 展开范围 | 每次打开抽屉都展开 | 抽屉关闭即销毁组合（`AppNav.kt:331`），行为最可预期 |

## 四、验收标准

1. 打开抽屉：电脑列表直接可见，无需点击首行。
2. 仅一台在线且未连接时进入如意：自动连接成功，抽屉首行显示该机名 +「当前连接 · 在线」，列表该行带「当前」标记，会话列表有内容。
3. 两台及以上在线：不自动连接，首行仍为「选择一台电脑」/「N 台在线」。
4. 全部离线：不自动连接，首行「选择一台电脑」，副标题「全部离线」。
5. 手动断开后停留 60s（覆盖 20s 轮询）：不会被自动连回去；手动连任意一台后，抑制解除。
6. `./gradlew :ruiyi-remote-ui:assembleDebug` 通过。

- 无外部依赖。真机验收需登录态与至少一台在线的桌面端（或中继侧可控 mock）。

## 六、影响评估

- 改动文件：`ruiyi-remote-ui/src/main/kotlin/com/xxt/zl/ai/ruyiremote/ui/RemoteSession.kt`、`.../ui/screen/SessionDrawer.kt`。
- 接口契约 / 数据结构 / 权限：均无变更。
- 未改动 `ConnectionEpoch`、切主机返回栈（`stackAfterHostSwitch`）、`watchTransport` 重连退避。
- 行为变化面：登录后首次进入如意会自动建立一条链路，中继侧会多一次 `connect` 记录（预期行为）。
- 风险：自动连接与用户手动断开存在竞争窗口 → 以抑制标记规避；轮询重复触发 → 以已尝试集合规避。
- 测试缺口：无自动化测试，验收依赖真机手测（列为待确认项）。

## 七、回滚方案

- 整批改动为单个提交，`git revert <commit>` 即可回到改动前。
- 仅回退某项：把 `SessionDrawer.kt` 的 `hostsExpanded` 初值改回 `false`；或删除 `refreshHosts()` 中的 `autoConnectSoleOnlineHost()` 调用（其余标记逻辑为死代码，不影响行为）。
