## Magpie 路由策略

证据：[网关分析](../../../../magpie/docs/gateway-routing-analysis.md)、[候选与回退](../../../../magpie/internal/gateway/fallback.go)、[排序策略](../../../../magpie/internal/routes/strategies.go)、[会话亲和](../../../../magpie/internal/gateway/affinity.go)、[休息状态](../../../../magpie/internal/gateway/routing.go)、[并发分散](../../../../magpie/internal/gateway/burst.go)。

1. 模型解析及替身映射后展开路由组；按模型、Provider 和 Key/账号生成候选，过滤禁用、权限及配额限制，并考虑协议适配。
2. Smart 默认结合配额使用率、续期及余额等信号；另有顺序、轮询、加权、LeastUsed、Pace、Drain、免费优先和速度、价格相关策略。LeastUsed 依赖配额使用率，不等同本地 Token 最少。
3. Session、Turn、Off、Auto 控制会话亲和；Auto 依据缓存价值和冷却时间决定是否保持账号。
4. 响应尚未对客户端输出时才可尝试其他候选；失败者根据限流、额度和失败类型进入不同休息状态。等价候选可依据在途请求数分散并发。

## Mika 现状

- [ProviderStore](../../app/src/main/java/com/wangzan101/mika/settings/ProviderStore.kt) 按用途构造单个模型；Provider 和独立凭据可作为候选基础，但各类账号登录多实例能力待验证。
- [RetryPolicy](../../core/src/main/kotlin/com/wangzan101/mika/core/agent/RetryPolicy.kt) 提供同模型重试及等待预算；[ModelError](../../core/src/main/kotlin/com/wangzan101/mika/core/model/ModelError.kt) 提供错误分类。可重试不等于可安全跨候选切换。
- [ChatModel](../../core/src/main/kotlin/com/wangzan101/mika/core/model/ChatModel.kt) 提供流式回调；安全切换边界已核实，结论见下节。

## 安全切换边界（已核实）

依据 [ModelCaller.kt](../../core/src/main/kotlin/com/wangzan101/mika/core/agent/ModelCaller.kt#L166-L231) 的 `complete()` 与 `routed()`。

1. **唯一发请求点**：所有上游请求都经 `complete()` 发出；工具由调用方在拿到 `ModelReply` 后才派发，故 `complete()` 内部无工具副作用，在它之内换候选不会重复执行工具。
2. **出字后换源已有先例**：`ModelError` 分支先 `onText?.invoke("")` 再判定是否重试，`routed()` 的「轻量模型 → 主模型」降级同样先清屏再改问主模型，说明「已显示文本后换源并清屏」是本仓库既有且被接受的行为，跨候选切换不引入新的语义类型。
3. **超长不跨候选**：`ContextTooLong` 走压缩后重试，不消耗候选顺序，也不应触发改源。
4. **残留风险**：切换会造成用户可见文本闪断；`ChatGpt` / `Xai` 等账号登录型 Provider 的跨账号切换涉及服务端会话态，未验证，一期不纳入。

## 建议架构与接口草案

每个用途可关联扁平候选组，成员引用现有 Provider/模型并包含顺序或权重。模型外部协议不变；内部选择器、配置格式、候选身份、错误映射、跨候选重试预算和旧配置迁移契约均待确认。默认继续现有单模型行为；候选变更可能改变模型能力、成本及数据发送方，须明确授权和能力约束。

## 一期范围建议稿（待确认）

1. **纳入**：扁平候选列表（成员引用现有 Provider/模型）、顺序与轮换排序、安全故障转移、失败冷却、在途计数、重试与切换共用预算、候选数据发送方提示。
2. **不纳入**：会话/轮次亲和、Smart/Pace/免费到期/配额 LeastUsed、加权与价格排序、嵌套组、跨设备状态共享、账号登录型 Provider 的跨账号切换。
3. **配置**：只在现有 Provider 配置上追加可缺省的候选字段，不改既有字段语义；字段缺省即单模型，行为与现在一致。

## 回退边界（双层）

1. **运行时边界（自动）**：仅在响应尚未发送、且错误属可切换类型（`RateLimited`、`Network`、`StreamCut`、`Server 5xx`、`QuotaExceeded` 等）时切换；`Auth`、`ModelNotFound`、`ToolsUnsupported`、`ContextTooLong`、`DailyBudgetExceeded`、用户取消一律不改源，沿用现有报错或压缩路径。切换不单设次数上限，与 `RetryPolicy.taskWaitBudgetMs` 共用预算，超预算即终止并报告最后一个错误。
2. **发布边界（人工）**：提供总开关；关闭时回落落档前的单模型 `modelFor(role)` 路径，不删除用户已配置的候选数据。发布或验证失败即关开关，而不是回滚数据。
3. **不可回退项**：已消耗的 token 与已发出的数据无法撤回，故切换时须把「请求可能发往另一 Provider」作为已知代价写入用户可见说明。

## 影响、兼容与回滚

预计影响模型装配、调用链、设置和持久化；具体改动文件、权限、性能与兼容性待核查。流式输出、工具副作用、取消及并发必须纳入验证。实施前应保留原配置及单模型路径；若发布或验证失败，按「回退边界（双层）」关闭总开关回落原路径，不删除用户数据。该回滚不同于运行时候选故障时停止并报告错误的兜底。
