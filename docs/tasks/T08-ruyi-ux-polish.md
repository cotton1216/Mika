# T08 如意交互与渲染四项补齐

- **任务ID**：T08
- **状态**：doing（真机验收 4 通过 / 2 未能构造触发条件，待用户判定是否结项）
- **责任人**：AI 执行，用户验收
- **更新时间**：2026-11-17

## 一、目标

1. 抽屉里的电脑列表「有列表就让位」：会话或任务已有内容时默认收起，连接中/失败仍强制展开。
2. 远程主机下发的 ` ```svg ` 代码块在手机端渲染成图，不再显示源码。
3. 模型调用失败、输出被中断、消息发送失败三类失败给「重试/重新发送」入口。
4. 模型选择面板左上角补关闭 icon（点外部关闭为现有行为，保留）。

## 二、范围

**本期做**：上述四项，命中 `ruiyi-remote-ui` 的 `SessionDrawer`、`MarkdownContent`、`ChatScreen`、`SessionChat`；新增 AndroidSVG 依赖。

**本期不做**：
- Markdown 行内图片（`![alt](url)`）与 `data:` URI 图片；
- SVG 作为附件上传/预览；
- 后台任务失败重跑（主机只暴露 `job/kill`）；
- 新增 `session/retry` 协议。

## 三、方案要点

| 项 | 方案 | 关键约束 |
| --- | --- | --- |
| 抽屉 | `hostsExpanded` 初值 = `sessions.isEmpty()`；`LaunchedEffect` 在列表到达后收起；用户手动拉过（`hostsToggled`）则不再自动收起 | 连接中/失败的强制展开不动 |
| SVG | `MarkdownBlock.Code` 判定为 SVG 时走 `SvgContent`：AndroidSVG 解析 → `renderToPicture` → Bitmap，8MB LruCache | 超 200k 字符、解析失败、尺寸无效一律降级为代码块 |
| 重试 | 发送失败 → `resend(row)`（先摘掉失败行再重发，不产生重复气泡）；本轮失败/被中断 → `retryLastTurn()`（重发上一条提问） | 无 retry RPC，重发会多一轮消息 |
| 弹窗 | 头部 Row 左侧加 `GlyphClose`，沿用 `onClose` | 点遮罩关闭保持原样 |

## 四、验收标准

1. 连上一台有会话的电脑，打开抽屉：电脑列表收起，直接看到会话。
2. 未连接 / 没有会话时打开抽屉：电脑列表展开。
3. 点某台电脑正在连接时：电脑列表自动展开。
4. 含 ` ```svg ` 的回复显示为图片；损坏的 SVG 显示为代码块且不崩溃；列表滚动不重复光栅化（缓存命中）。
5. 断网发送消息 → 该条显示「发送失败」+「重新发送」，点击后重发且不出现两个气泡。
6. 模型调用失败（「本轮失败：…」）与会话被中断时出现「重试」，点击后重发上一轮。
7. 模型面板左上角出现关闭 icon，点击关闭；点面板外部同样关闭。

## 五、阻塞与依赖

- 新增 `com.caverock:androidsvg-aar:1.4`，需 Gradle 能拉到该依赖；拉不到则退 WebView 光栅化（已与用户约定）。
- 真机验证需要至少一台在线电脑；SVG 用例需要主机在回复里产出 SVG 代码块。

## 六、影响评估

- 新增 1 个第三方依赖（约 150KB），需重新出包。
- 只动渲染层与交互层；协议、数据结构、权限均无变更。
- 抽屉默认态变化会影响首屏观感：从「先看电脑」变为「先看会话」。

## 七、回滚方案

四项互相独立，可单点回退：抽屉改回 `mutableStateOf(true)` 并删除 `LaunchedEffect`；SVG 删 `looksLikeSvg` 分支；重试移除按钮与两个方法；图标删该 `GlyphAction`。

## 九、真机验收结论（2026-11-17 14:20–14:55，大苹果 Host）

**环境**：日常机 `33325df`（miro / Android 17），release 包 `如愿-0.1.50-arm64-v8a-release.apk`（`CN=…, OU=Mobile, O=XXT`，SHA-256 `5c448ff7…bbde0d`）。构建参数 `-PapphubBaseUrl=https://ai.thchengtay.com/apphub`。机内原有 code 52 更高版本，直接 `install -r` 报 `INSTALL_FAILED_VERSION_DOWNGRADE`，`-d` 也不放行；做法是临时把 `ruyiVersionCode` 改成 52 重新打包安装，**装完立即改回 51**（工作区无残留）。

**未过项的性质**：3 与 6 都是「触发条件构造不出来」，不是行为错误。6 的正向路径依赖 Host 真的把 `turn/end reason.kind=error` 发下来，客户端无从伪造；3 依赖连接过程能被肉眼/`dump` 观察到。

**附带发现（不在 T08 范围，建议单独立项）**：
1. **发送失败的行会被输入框盖住**：列表在用户上滚状态下不会因为「新插了一条失败消息」自动滚到底，失败提示与「重新发送」正好落在输入框下方，`bounds` 甚至是 `0,0`，要手动上滑一格才点得到。
2. **断网重连后聊天页被替换**：连接断开超过重连窗口（约 82s）会退回「还没有连接到这台电脑」，重新连上后回到的是会话列表而不是原会话，本地那条失败消息一并消失——失败重试实际上只在断网后约 82s 内、且手动滚一下才用得上。
3. 流式输出途中断网，正在分析的助手行不会立刻标「输出被中断」，会一直停在「某某模型正在分析」，直到重连窗口耗尽整页被替换。`AssistantRow.interrupted` 只认 Host 下发的 `interrupted=true`，客户端自己判不出。
4. 历史消息里的 `![alt](<xxx.svg>)`（Markdown 行内图片）仍按纯文本显示——本期范围已声明不做，但用户在 11-16 那条「儿童游乐场」会话里已经产出过这种形态，后续可能被要求补上。
